# Tag Prefix

## Schema

1. A tag's prefix shall conform to the prefix schema defined by a tag's discipline.
1. The schema is a jsonb field, which reads as a Ruby hash in the discipline model.
1. The schema requires a name element.
1. If the name corresponds to a standard schema key as defined in Constants, that is all the required information. The schema will be loaded from Constants when required.
1. If the name isn’t in the standard list, it is considered a custom schema. A custom schema also requires a type element, and the type must be one of the four available types: :default, :dim1, :dim2, and :isa51. The type controls the code used to build the user form with select options, or to parse an existing prefix.
- :isa51 is a nested hash conforming with the ISA Standard 5.1: Instrumentation Symbols and Identification.
- :dim1 is a single dimensional list of allowed prefixes, with their element types.
- :dim2 is a hash with two parts of variable character length, and the prefix must at least match an item in the first part.
- :default is freeform string, no parsing occurs.
1. When displaying a tag with the show view or the card partial, the prefix is to be parsed by the method prefix_parts in the Tag class. The parts vary depending on the schema type, and the views shall adapt to the content of prefix_parts.  If a standard schema is in use, the views shall translate the schema values, but not the keys. 1. The tag form partials have variable content controlled by a [stimulus controller](app/javascript/controllers/tag_controller.js). The prefix field will return the value of the prefix for params. This field will be a normal bootstrap_forms text_field when the schema type is :default. When the schema type is :dim1, :dim2, or :isa51, the field will be a read only field with content generated by concatenating the prefix parts select fields.
1. When the schema type is not :default, appropriate select tag fields will be added to the form. They shall not be included in the tag params. These select fields shall be initialised with the values provided by prefix_parts.
1. Tags can only be built within a discipline, so the prefix schema is known at the time of showing the form or of creating the tag.
1. When any of the prefix parts fields are changed, the controller shall update the prefix field. This should in turn trigger the update of the full tag element in the partial header.
1. The [partial prefix_fields](app/views/tags/_prefix_fields.html.erb) is used to interface between the ruby controller and view, and the javascript form controller.
